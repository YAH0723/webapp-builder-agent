## 问答准备

1. 和参考实现的区别是什么？已有 BM25、自动修复与 TDD 不算新增；本组拟增加跨层追踪、基于失败证据的影响分析和可量化的预算策略。
2. 为什么能提高分数？目前是待验证假设；通过真实失败类别、对照实验和消融支撑，不能只凭架构复杂度推断。
3. 如何证明通用性？BookStack 仅用于首轮诊断；同一 Agent SHA 在不同业务的第二任务运行，并用自定义自然语言需求展示用户流程。若依据第二任务调参，明确它已成为开发集。
4. 如何保证比较公平？固定任务、模型、预算与环境，重复独立生成，报告通过率和成本及波动。
5. 如果没有提分？报告收益不成立的证据、瓶颈和回退方案；可以证明成本降低或错误定位更有效，但要有数据。
6. 能否在自动评测中交互？自动模式不能等待人类；需求澄清只用于本地可选模式。

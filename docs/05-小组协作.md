# 小组协作与首批任务

成员人数和 GitHub 用户名尚未提供。以下按四个职责设计；可以一人兼任，不代表必须有四人。

| 职责 | 负责人（待填） | 首周产出 | 互审对象 |
|---|---|---|---|
| A 集成与平台 | 待填 | 官方任务/入口适配、B0 提交、可复现环境 | B |
| B 需求与后端 | 待填 | 需求追踪、契约与持久化失败修复 | C |
| C 前端与验收 | 待填 | 关键 UI 链路、状态/时钟检查、失败截图 | B |

每人至少负责一个可验收任务并评审其他成员的一个 PR。两人组可 A+D、B+C；三人组可合并 A+D。每天简短同步“完成/证据/阻塞/下一步”，合并前由另一个成员阅读改动与验证记录。

## GitHub 规则

仓库建议 `arcbench-bookstack-final`，初始使用私有可见性。保留上游历史；`upstream` 指向参考实现且本地禁用其 push URL；`origin` 指向小组仓库。不要把组员加入上游库。

1. 用户登录 GitHub 创建空仓库，不初始化 README/.gitignore/License。仓库名可改，脚本使用真实 URL。
2. 在项目根目录运行 `team-tools/Connect-GitHub.ps1 -RepositoryUrl https://github.com/OWNER/REPO.git`，它校验 URL、设置 origin，并将当前 main 推送。身份验证由 Git Credential Manager 完成。
3. 仓库所有者到 Settings → Collaborators 邀请组员 GitHub 用户名；成员接受邀请。用户名未知，当前不发送邀请。
4. 每人 clone 自己的小组库。不要提交 .env、原始 API 日志、平台密钥、本地依赖、生成目录和未脱敏材料。
5. 成员从 main 创建 `feat/traceability`、`fix/session-state`、`exp/context-budget` 等分支，经 PR 互审合并；主分支始终保持可运行。
6. 若账号套餐支持，可设 main 的 PR/评审及状态检查规则；这不是当前已启用的保护。

```powershell
git switch main
git pull --ff-only
git switch -c feat/traceability
# 开发与验证后，只暂存相关文件
git add <相关文件>
git commit -m "feat: link requirements to acceptance evidence"
git push -u origin feat/traceability
```

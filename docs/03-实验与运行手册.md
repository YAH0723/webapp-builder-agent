# 实验与运行手册

## 本地准备（在仓库根目录执行）

需要 Python 3.11+、Node.js 22.12+、npm、uv。SQLite 原生模块在 Windows 可能需要 Visual Studio C++ Build Tools。先核对本机版本，再执行：

```powershell
uv sync
uv run playwright install chromium
Copy-Item .env.example .env  # 仅首次；已有配置不要覆盖
```

自行在本地 .env 配置有效模型和 API 凭据，不提交真实密钥。当前只建立项目，未执行付费模型调用，也没有完成平台评测。

先从平台下载完整 BookStack 需求、参考图片与官方 Agent Template，保存在忽略目录 `tasks/bookstack/`。核对 requirements.yaml 引用的每张图片，记录任务版本/文件摘要。不要用当前认证示例的测试结果冒充 BookStack 得分。

```powershell
uv run main.py tasks/bookstack --output-dir outputs/B0-r1
Set-Location outputs/B0-r1
npm run db:init
npm run build
npm start
```

更详细模型日志可用 `--model-log`，但其中可能含请求数据，先保存本地原始目录，脱敏后再共享。保留生成目录中的 `.arc/compilation.json`。开发检查与平台得分独立记录。

## 平台首交清单

1. 确认本次 BookStack 正式需求、测试数量、时钟和 UI 状态建立规则。
2. 按 Agent Template 协议准备 runtime entrypoint；ZIP 根目录直接包含入口。
3. 评测模式读取平台注入的 OPENAI_BASE_URL / OPENAI_API_KEY；不打包本地真实 .env，不写死端点和密钥。
4. 安装依赖、执行入口、生成应用、启动服务的冷启动路径完整可复现。
5. 记录提交名、commit SHA、包 SHA256、模型、预算、运行 ID、官方报告和错误日志。
6. 只有正式平台报告才能支撑正式分数；本地验收仅用于诊断。

注意：上游 `scripts/package.py` 明确会把 `.env` 包入 ZIP，即使它被 Git 忽略。首次提交前须修正或使用独立干净的发布目录，并逐项检查 ZIP。当前没有生成提交 ZIP。

## 公平对比与指标

- B0：冻结上游基线及必要平台适配；V1：只加入追踪/局部修复；V2：再加一种成本优化。平台适配保持各组一致。
- 固定任务版本、模型版本、模型参数、超时、修复/调用预算、初始数据和运行环境。任务状态每次从干净环境建立。
- 每版本尽量至少 3 次独立生成；总预算不足时先做小样本筛选，在结论中标注局限。评测次数不等于独立生成次数。
- 通过率 = 官方通过测试数 / 当次实际总测试数；完整成功率 = 所有测试通过的独立运行数 / 运行数。
- token 统计全流程输入/输出，包含视觉、修复、失败和重试。未返回 usage 的调用标记 missing，不能记作 0。
- 耗时分开记录生成、启动、评测及总墙钟时间；报告均值与范围。成本以平台实际账单为主。
- 消融：B0、B0+追踪与修复、B0+成本优化、组合版本；若运行预算有限，先比较 B0/V1，再选用消融。
- 失败按输入/入口、需求遗漏、状态/持久化、契约不一致、UI 交互、视觉、环境、模型输出、预算超时归类。

`experiments/runs.csv` 仅包含表头；每次真实运行填写一行。`failures.csv` 用于根因追踪，示例不预填虚构结果。原始报告保存 `experiments/raw/<run_id>/`（不入 Git）；脱敏摘要与截图按需提交。

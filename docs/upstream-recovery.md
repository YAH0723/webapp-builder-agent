# B2.2R1：上游服务故障恢复

此分支从 B2.2 固定提交 `7cc76e12995f72158c68b379a913da05fd007ac4` 派生，不包含 B2.3 的功能骨架与诊断实验。

## 故障与处理

模型服务失败会导致 schema 关联或需求读写义务缺失。后续严格读取这些记录时会失败，API 契约无法生成；继续进行页面实现会消耗资源，最终应用缺少后端与业务交互。

本层在图片分析、schema、读写义务、API 设计中加入一次延后补跑：先尝试其他任务，再等待 5 秒，仅重试 HTTP 408/409/429 限流/500/502/503/504 或 SDK 连接/超时失败的任务。通过异常链判断，余额/配额不足、认证错误、JSON 或业务契约错误不视为临时服务失败。已有成功结果不重做，失败记录不伪造为空数据。每次补跑沿用原任务预算，因此故障恢复可能额外消耗费用；SDK 自带传输重试保持不变。

执行依赖阶段前，校验所有叶需求的 schema 关联、需求和场景步骤的义务，以及完整后端契约。关键记录不全时标记 `BLOCKED`，保留缺失原因与已有产物，阻断依赖任务的生成。CLI 在此情况下返回 2，避免把缺少关键生成阶段的应用声明为成功。普通测试失败仍沿用原有部分产物行为。

`ARC_B2_SERVICE_RECOVERY=0` 关闭该层。每个阶段最多一个延后补跑轮次；服务持续不可用仍会失败。补跑状态位于 `.arc/task_recovery/`，最终状态位于 `.arc/compilation.json`。

## 验证与打包

```sh
uv run python -m unittest discover -s tests -p test_service_recovery.py -v
uv run python team-tools/package-baseline.py --variant B2.2R1
```

故障注入检查使用脚本模型：图像、schema 和义务中的临时 503 恢复后，保留邻近成功任务；同类故障持续存在时有界终止；缺失义务不默认置空；依赖不完整时不调用昂贵生成；BLOCKED CLI 返回非零。另有 13 阶段流程检查，模型输出为空业务的合法结构，依赖安装和数据库运行验证被隔离，不代表完整网站生成或官方分数。
